## Capture sequence

1. Record the frozen commit SHA, app version, bundled pack ID/version, local date, Android device/API and Desktop OS. Use one fictional profile and the same date for comparisons. Clear notifications and private browser tabs before starting.
2. Launch the built Android app on a device or emulator and the packaged Desktop app, not a Compose preview. Complete the two-step onboarding on a clean local profile, showing that the IELTS lesson is synthetic and separate from Linh's sourced pack. Verify the **zero** opened doors in that 15-door pack before filming any Route claim.
3. Capture each row above at native resolution. On Android, `adb exec-out screencap -p > A1.png` saves a screenshot of the active screen. On macOS Desktop, `screencapture -x D1.png` saves the screen; crop to the app window during editing without changing UI content. Use descriptive filenames if the final capture location differs.
4. Record the 3–5 minute screencast from the same build. Keep the pointer visible on Desktop, magnify small receipts in the edit, and caption official URLs, source-review dates, simulated values and the saved-profile warning so they remain readable in the uploaded video.
5. Review each exported image and the final video at the actual submission size. Check text overflow in English and Vietnamese, keyboard focus on Desktop, dark-mode contrast, disclosure visibility, zero-open-doors wording and synchronization between narrated claims and shown state. Retake any failed shot.
6. Fill the asset register below with the source screenshot or recording filename and final exported path. Keep the unedited original privately for audit and use only reviewed media in the submission.

## Capture rules

- Capture from the frozen/tagged app, not a design mockup or old Roborazzi golden. Do not make Web screenshots or Web run claims.
- Use only the fictional sample profile; do not show a real student's personal or academic data.
- Keep text readable at the final upload size and avoid cropping source/trust disclosures.
- Use identical sample facts, pack version, and local date where comparisons are claimed.
- Linh's current sourced 15-door pack opens zero doors; a simulated path can improve checks without opening a door. Label any synthetic preview as illustrative.
- Show both language modes only after checking translated controls and overflow at final capture size.
- Do not edit UI content after capture. Permitted edits are crop, scale, safe background, and redaction of OS chrome.
- Record the commit SHA, platform, viewport, theme, date, and source file for every exported asset.

## Rights audit

- Confirm license/origin for every bundled font, icon, illustration, audio track, and overlay.
- Preserve the starter-kit license and dependency notices.
- Do not use provider logos as decorative endorsements.
- Obtain written permission for every identifiable third party or third-party voice in the screencast.
- Use no copyrighted music unless the submission has a documented license allowing this use.
- Review filenames, notifications, browser tabs, bookmarks, and desktop wallpaper for private information.
